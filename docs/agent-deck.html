The signal language

Color says what. Motion says how urgently.

Four states, and only two of them move — so a mostly-still deck with one breathing key and one pinging key is instantly scannable.

Working

Breathing gold + shimmer

Mid-turn, using tools. The orb pulses and a light sweeps across it, like Claude thinking. Leave it be.

Needs you

Crimson sonar + flash

Blocked on your input or a permission. Rings ping outward and the rim breathes — the one state that earns real urgency.

Done

A pop, then it holds

Finished a task and still alive. It flares green, then settles — a steady state you can rely on, distinct from a sleeping chat.

Idle

Dim, still, receding

No live session behind that key. It fades into the deck so the lit keys keep your attention.

How it works

From a keystroke in Claude to a glow on the desk.

Two halves that never call each other: Claude Code just drops small files as it lives its life, and a Stream Deck plugin reads them and paints. Loosely coupled, so nothing blocks.

1

Hooks fire

A tiny script wired to every Claude Code lifecycle event — PreToolUse, PermissionRequest, Stop — decides a status. Global, so every session reports.

2

Status files

Each session writes one small JSON — status, emoji, timestamp — into ~/.claude/state. One file per agent, no races.

3

The bridge

The sidebar knows a chat by its conversation id; the hooks stamp files with the transcript id. A mapping file the app keeps stitches the two.

4

The plugin paints

A Node plugin reads the files once a second and repaints keys ~15× a second — each key a single animated SVG orb.

5

Your deck

One key per chat in a chosen sidebar group. Drag to arrange; press to jump back to Claude.

The hooks, event by event

Eight lifecycle events, one script, four colors.

This is the part that makes it possible at all. Claude Code can run a command on any moment of a session's life — I wired eight of them to the same tiny script. It reads the event on stdin, decides a status, writes one file. Here's the whole truth table.

The contract

stdin in, one file out

Every fire hands the script a JSON blob — session_id, cwd, hook_event_name. It writes agent-status/<id>.json atomically and always exits 0, so a hook can never block or break a turn.

Global by design

Every session reports

Wired once at the user level in settings.json, so any Claude Code session — any project, any window — lands on the deck automatically. Zero per-project setup.

Cheap

Bash + jq, nothing else

No Node, no network on the hot path — just jq reading stdin and an atomic file write. The latency it adds to a turn is imperceptible.

The stack, byte by byte

Small on purpose — one SDK, some SVG, and tiny text files.

No database, no server, no image assets. The keys are SVG strings drawn on the fly; the two halves talk only through a handful of JSON files. The one heavy thing is the Elgato SDK folded into the bundle.

Where it lives on disk

Three homes on one Mac.

Nothing is global or hidden — it's Claude's config folder, the app's data folder, and a normal project folder. Delete those and it's gone.

~/.claude/ Claude Code side — the producer ├─ hooks/agent-status.sh writes status on every event ├─ agent-emojis.json per-project emoji overrides ├─ settings.json the hooks block that wires it up ├─ skills/streamdeck-sync/ the /streamdeck-sync skill └─ state/ ├─ agent-status/*.json live status, one file per agent └─ streamdeck-group.json the deck's chat list ~/Library/Application Support/Claude/ the app's own data — the bridge └─ claude-code-sessions/**/local_*.json conversation id ↔ transcript id ~/Development/claude-agent-deck/ the Stream Deck plugin — the consumer ├─ src/plugin.js the source you edit ├─ com.tknab.claudeagents.sdPlugin/ │ ├─ manifest.json │ └─ bin/plugin.js esbuild bundle (what runs) └─ package.json the build script ~/Library/…/com.elgato.StreamDeck/Plugins/ └─ com.tknab.claudeagents.sdPlugin → symlink to the dev folder

Stream Deck loads the plugin by that symlink, so npm run build + a restart is the entire edit loop — no reinstall.

Under the hood

Four decisions that make it feel right.

Ordering

Draggable, and it sticks

Each key owns its chat through settings that travel with the key when you drag it. Rearrange the deck however you like — the arrangement survives restarts. No mirroring the sidebar, because that reorders itself by activity.

The gotcha

Two ids, one chat

The colors were dead at first: the group spoke conversation ids, the status files spoke transcript ids. The fix reads the desktop app's own map — local_<convId>.json → cliSessionId — live, so a resumed session still lines up.

Membership

A one-word sync

Run /streamdeck-sync and the deck mirrors whichever chats are in the group — emoji and label pulled straight from each chat's title, which you set as {emoji} {short title}.

The look

Cross-fades for free

The orb color eases toward its target every frame instead of snapping. So working melts into done, done holds, and any change reads as a smooth transition — one trick, every state.

Could this ship?

On listing it in the Marketplace.

Short answer: the concept absolutely could — and it packages in one command — but what's on the desk today is a personal tool wearing a beautiful coat. Here's the honest gap.

Verdict · promising, not yet

A great concept, a few days from shippable.

streamdeck pack already produces a .streamDeckPlugin installer, and Elgato's Marketplace takes free submissions through the Maker portal. The blocker isn't packaging — it's that this build assumes my machine.

It reads hand-installed Claude Code hooks, hard-codes macOS paths, and leans on an undocumented app file format for the id bridge — which could shift under any Claude update. Fine for me; fragile for strangers.

  • Set-up flow. Ship the hooks for the user instead of assuming ~/.claude is already wired.
  • Cross-platform. Windows paths + a graceful "no Claude Code found" state.
  • Version the bridge. Treat Claude's internal files as unstable — guard and degrade, don't crash.
  • Property Inspector. Let users pick the group and tune colors in the UI.
  • Brand check. Clear the "Claude" name & mark against Anthropic's guidelines before anything public.
